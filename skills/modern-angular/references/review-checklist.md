# Review checklist

Severity: **bug** breaks behaviour now or under zoneless; **risk** works today but breaks easily or leaks; **modernize** is the documented better API. Report each finding with the angular.dev link given here.

## Correctness traps

| Look for                                                                                                                                         | Severity  | Why, and the fix                                                                                                                                               | Source                                                                                                                                   |
| ------------------------------------------------------------------------------------------------------------------------------------------------ | --------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| An `effect` that calls `.set()` or `.update()` on another signal to keep it in sync                                                              | risk      | Effects that propagate state can loop or throw `ExpressionChangedAfterItHasBeenChecked`. Derive with `computed`, or `linkedSignal` if the user can also set it | [use cases for effects](https://angular.dev/guide/signals/effect#use-cases-for-effects)                                                  |
| An `effect` that reads a signal after `await`                                                                                                    | bug       | Reads after an `await` are not tracked, so the effect will not rerun for them. Read before the `await`                                                         | [async operations](https://angular.dev/guide/signals#reactive-context-and-async-operations)                                              |
| An `effect` that starts a timer, listener or request without `onCleanup`                                                                         | risk      | Work from the previous run keeps going. Register `onCleanup`                                                                                                   | [cleanup functions](https://angular.dev/guide/signals/effect#effect-cleanup-functions)                                                   |
| `@for` with `track $index` or `track item` over a list that changes                                                                              | risk      | Angular cannot match rows to data; slow re-rendering and lost DOM state. Track a unique id                                                                     | [why track matters](https://angular.dev/guide/templates/control-flow#why-is-track-in-for-blocks-important)                               |
| `*ngFor` with no `trackBy`                                                                                                                       | modernize | Same problem in the old syntax. Migrate to `@for` with `track item.id`                                                                                         | [control flow migration](https://angular.dev/reference/migrations/control-flow)                                                          |
| `.subscribe(` with no `takeUntilDestroyed`, `toSignal`, `async` pipe or `DestroyRef` teardown, on an Observable that does not complete by itself | bug       | The subscription outlives the component                                                                                                                        | [takeUntilDestroyed](https://angular.dev/ecosystem/rxjs-interop/take-until-destroyed)                                                    |
| `takeUntilDestroyed()` without an argument outside the constructor or a field initializer                                                        | bug       | It needs an injection context; pass `inject(DestroyRef)`                                                                                                       | [takeUntilDestroyed](https://angular.dev/ecosystem/rxjs-interop/take-until-destroyed)                                                    |
| `toSignal(...)` inside a method or getter called more than once                                                                                  | risk      | Each call opens a new subscription. Create it once in a field                                                                                                  | [toSignal](https://angular.dev/ecosystem/rxjs-interop#create-a-signal-from-an-rxjs-observable-with-tosignal)                             |
| A plain field shown in the template and assigned in `subscribe`, `setTimeout`, a promise or a third-party callback                               | bug       | Under zoneless (default since v21) nothing notifies Angular, so the view stays stale. Use a signal                                                             | [zoneless requirements](https://angular.dev/guide/zoneless#requirements-for-zoneless-compatibility)                                      |
| Mutating an array or object that a child receives as an input (`push`, property writes)                                                          | bug       | `OnPush` (default since v22) compares inputs with `Object.is`; an in-place change is not a new value. Replace the value                                        | [using OnPush](https://angular.dev/best-practices/skipping-subtrees#using-onpush)                                                        |
| `NgZone.onStable`, `onMicrotaskEmpty`, `onUnstable` or `isStable`                                                                                | bug       | They never emit, or are always true, without zone.js. Use `afterNextRender` / `afterEveryRender`                                                               | [NgZone observables](https://angular.dev/guide/zoneless#remove-ngzoneonmicrotaskempty-ngzoneonunstable-ngzoneisstable-or-ngzoneonstable) |
| A template bound to reactive form state with no notification path                                                                                | bug       | `setValue` and `patchValue` do not schedule change detection in zoneless apps                                                                                  | [reactive forms in zoneless apps](https://angular.dev/guide/zoneless#reactive-forms-in-zoneless-applications)                            |
| `resource.value()` / `httpResource.value()` read without `hasValue()`                                                                            | bug       | `value()` throws in the error state                                                                                                                            | [resource status](https://angular.dev/guide/signals/resource#resource-status)                                                            |
| `httpResource` used for `POST`, `PUT`, `DELETE`                                                                                                  | risk      | It fires eagerly and re-fires when its signals change. Use `HttpClient` for mutations                                                                          | [using httpResource](https://angular.dev/guide/http/http-resource#using-httpresource)                                                    |
| A `viewChild()` result used without handling `undefined`                                                                                         | bug       | Single-result queries are `undefined` when the element is not rendered. Use `.required()` only when it always is                                               | [required queries](https://angular.dev/guide/components/queries#required-queries)                                                        |
| A component writing state into a child or parent through a query                                                                                 | risk      | Brittle and prone to `ExpressionChangedAfterItHasBeenChecked`                                                                                                  | [query pitfalls](https://angular.dev/guide/components/queries#common-query-pitfalls)                                                     |
| `afterRenderEffect(() => ...)` without phases doing DOM reads and writes                                                                         | risk      | Runs in `mixedReadWrite` and can cause extra reflows                                                                                                           | [render phases](https://angular.dev/guide/signals/effect#render-phases)                                                                  |
| `ChangeDetectionStrategy.Default`                                                                                                                | modernize | Deprecated; it means `Eager`                                                                                                                                   | [ChangeDetectionStrategy](https://angular.dev/api/core/ChangeDetectionStrategy)                                                          |

## Modern API swaps

| Old                                              | New                                    | Source                                                                                |
| ------------------------------------------------ | -------------------------------------- | ------------------------------------------------------------------------------------- |
| `@Input()`                                       | `input()` / `input.required()`         | [inputs](https://angular.dev/guide/components/inputs)                                 |
| `@Output() x = new EventEmitter()`               | `output()`                             | [outputs](https://angular.dev/guide/components/outputs)                               |
| `@Input() x` + `@Output() xChange`               | `model()`                              | [model inputs](https://angular.dev/guide/components/inputs#model-inputs)              |
| `@ViewChild`, `@ContentChildren`...              | `viewChild()`, `contentChildren()`...  | [queries](https://angular.dev/guide/components/queries)                               |
| `ngOnChanges` deriving fields                    | `computed`                             | [computed](https://angular.dev/guide/signals#computed-signals)                        |
| `ngOnDestroy` + `Subject` + `takeUntil`          | `takeUntilDestroyed()` or `DestroyRef` | [takeUntilDestroyed](https://angular.dev/ecosystem/rxjs-interop/take-until-destroyed) |
| `HttpClient.get(...).subscribe(v => this.x = v)` | `httpResource` (v22+) or `toSignal`    | [httpResource](https://angular.dev/guide/http/http-resource)                          |
| `*ngIf`, `*ngFor`, `[ngSwitch]`                  | `@if`, `@for`, `@switch`               | [control flow](https://angular.dev/guide/templates/control-flow)                      |
| `standalone: false` + NgModule                   | standalone component                   | [standalone](https://angular.dev/reference/migrations/standalone)                     |

Do not report a decorator as a bug: angular.dev keeps them fully supported. They are **modernize** findings.
